# 动画流（flow_see）

把任何有流程的事物或原理，做成可以观察、可以交互的动画，让它们更容易被理解。

## 项目目标

世界上有大量“按步骤发生”的事物：算法如何一步步执行、网络协议如何握手、
工作流程如何流转、科学原理如何演化。纯文字和静态图很难表达“过程”本身。

**动画流**希望做到：

- 把流程类内容（算法、协议、工作流程、科学原理等）可视化为动画
- 支持观察与控制：播放、暂停、单步、回退、调速
- 让人一眼看清“每一步发生了什么、状态如何变化、为什么”
- 新增一个动画的成本尽量低，便于持续扩充内容

## 当前状态

第一版（M1–M5）已按[产品原型](./docs/产品原型.md)开发完成：

- **创建**：选模板 → 填步骤（默认两项，“更多设置”里有高级参数）→ 实时预览 → 自动保存
- **四种模板**：流程图流转、消息传递、数据变化（排序算法自动生成步骤）、循环/时间线
- **四种主题**：专业风、简洁扁平、卡通可爱、手绘黑板
- **播放器**：自动播放、字幕与朗读、单步/回退/跳转/调速/全屏、步骤目录、“试试改参数”
- **页面**：首页、动画广场（14 个官方动画，分类/类型筛选、搜索）、我的作品、设置、分享打开页
- **分享与导出**：短链接分享（自带服务端）、导出视频（MP4/WebM）与 GIF
- **App**：Capacitor 安卓与 iOS 工程，原生朗读、返回键、系统分享

## 本地运行

需要 Node.js 20+ 和 pnpm。

```bash
pnpm install
pnpm dev        # 前端开发服务器：http://localhost:5173
pnpm server     # 分享服务（另开一个终端）：http://localhost:8787，开发时 /api 自动转发到这里
pnpm test       # 单元测试（含服务端接口测试）
pnpm lint       # 代码检查
```

不启动 `pnpm server` 也能使用除“分享链接”以外的全部功能。

## 部署（网页）

```bash
pnpm build      # 类型检查并打包到 dist/
pnpm start      # 同一个 Node 服务同时提供网页和分享接口，默认端口 8787
```

可用环境变量：`PORT`（端口）、`DATA_DIR`（分享数据目录，默认 `server/data/shares`）。分享数据是一份份 JSON 文件，备份这个目录即可。

## 打包 App

1. 先把网页服务部署到公网，然后把 `.env.app.example` 复制为 `.env.app`，填上服务器地址（App 里的分享链接要指向公网）。
2. 运行 `pnpm build:app`（打包并同步到原生工程）。
3. 安卓：`pnpm cap:android` 用 Android Studio 打开并运行；iOS：`pnpm cap:ios` 用 Xcode 打开（需要 macOS）。

## 目录结构

```
src/
├── engine/      # 纯 TypeScript：作品数据结构、编辑、播放状态机、主题
├── templates/   # 动画模板（每个模板一个文件夹）及注册表
├── player/      # 播放器
├── editor/      # 编辑器组件
├── pages/       # 页面
├── content/     # 动画广场的官方内容与搜索
├── services/    # 本地存储、朗读、分享、导出、备份、原生能力
├── store/       # 编辑器状态、全局设置
├── ui/          # 通用界面组件（导航、对话框等）
└── styles/      # 全局样式与设计变量
server/          # 分享服务（无第三方依赖的 Node 服务）
android/ ios/    # Capacitor 原生工程
```
