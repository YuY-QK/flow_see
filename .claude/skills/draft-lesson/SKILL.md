# draft-lesson：数学知识点 AI 起草技能

本技能指导 AI 助手按照《小学数学开发手册》中的知识点脚本，为 flow_see 项目起草数学知识点的场景配置 YAML 文件（`packages/content/lessons/math/g<年级>/<id>.yaml`）。

---

## 1. 输入

- **知识点 id**（必填，如 `compare-within-10`、`compose-10`）。
- **年级**（可选，1–6；若未显式指定，可通过检索课程目录或 C 脚本定位）。

---

## 2. 执行前必须阅读的文档

起草前务必按顺序阅读并理解以下文档的约束与规范：

1. **`CLAUDE.md`**：项目总约定（配置优先、代码与配置分离、无硬编码常量）。
2. **`docs/小学数学开发手册/README.md` 第 2–4 节**：
   - 2 节：工作方式（单卡单分支、不扩大/降低要求）。
   - 3 节：完成标准（文件改动、测试、约定检查）。
   - 4 节：通用视觉规范（4.1 坐标与尺寸、4.2 颜色语义、4.3 动画规范、4.4 主题适配、4.5 包围盒）。
3. **`docs/小学数学知识点开发文档.md` 5.2 节、6.5 节、8.1 节**：
   - 5.2 节：知识点文件字段约定与四条画面核心规则。
   - 6.5 节：版式与用色规范。
   - 8.1 节：知识点逐条自校清单。
4. **`packages/content/lessons/scene.md`**：场景模板零件属性、动作语法、动手方式、文本标记（`[4](@r1)`、`[x](blank)` 等）用法。

## 3. 标准起草步骤

### 步骤 1：检索知识点脚本
在 `docs/小学数学开发手册/` 对应年级的脚本文件（`C-知识点脚本-一年级.md` 至 `六年级.md`）中搜索 `### \`<id>\``：
- 获取知识点位置（年级、单元、批次）、元信息（summary、tags、cover、related、recommended）。
- 获取舞台尺寸（低年级通常为 800 × 360，标准为 800 × 450）、参数定义 `params`、派生变量 `derived`、出题控件 `explore` 或预设 `presets`。
- 获取零件清单（`objects`）及几何位置。
- 获取步骤表（标题、讲解、画面动作、动手做）和核心要点（`keyPoints`）。

### 步骤 2：生成初始文件骨架
运行项目脚手架命令生成模板并更新课程目录：
```bash
pnpm lesson:new <年级> <id>
```
该命令会自动：
1. 校验 `packages/content/curriculum/math/grade<年级>.yaml` 中的注册项。
2. 将目录中的 `- { id: <id>, title: ... }` 改写为纯 id 形式 `- <id>`。
3. 在 `packages/content/lessons/math/g<年级>/<id>.yaml` 生成带有完整注释的骨架。

### 步骤 3：逐项翻译脚本并编写配置

#### 3.1 元信息
- `id`: 与文件名一致的小写英文标识。
- `title`: 课程目录中的中文标题。
- `summary`: 原文照抄，一句话说明学什么/怎么学（≤ 30 字）。
- `status`: 起草阶段一律设为 `draft`。
- `duration`: 根据步数与节奏取整（如 `1分钟`、`2分钟`）。
- `tags`: 3–6 个标签（知识点名、算式类型、关键零件、同义词）。
- `cover`: 必填 `text`（代表性算式或关键词，如 `"5 > 3"`、`"9 + 4"`）。
- `related`: 关联前置、进阶或跨年级同主题知识点 id 列表（最多 4 个）。
- `recommended`: 仅在脚本标有时设为 `true`，未标不写。

#### 3.2 舞台与参数
- `stage`: 严格按脚本尺寸填写（避免上下留大片空白）。
- `params`: 会变化的数字一律设为参数，给出标准取值。
- `derived`: 拆分量、得数、中间步骤由派生算式计算，讲解与要点中不写死由参数决定的数。
- `explore`: 按照脚本配置出题控件（滑块 `slider`、下拉 `select`），仅开放数学上讲得通的取值范围。

#### 3.3 零件定义（`objects`）
- 锚点规则：
  - 计数块（`counters`）、十格框（`tenframe`）、方格（`grid`）的 `at` 为**左上角**。
  - 数轴（`numberline`）的 `at` 为**最左端点**。
  - 文本、几何图形及其他零件的 `at` 为**几何中心**。
- 颜色规则：仅使用颜色名（`blue`、`orange`、`accent`、`line`、`ink` 等）或 `@零件id`，不写硬编码 hex 颜色值。
- 初始状态：需在后续步骤才出现的零件配置 `hidden: true`。
- 重复零件：使用 `repeat: "{n}"`，内部可用 `{i}` 作为从 1 开始的递增索引。

#### 3.4 步骤表（`steps`）翻译对照
| 脚本记号 / 描述 | 翻译为 YAML 配置 | 说明 |
|---|---|---|
| 讲解内容 | `say: "..."` | **原文照抄**；讲解内 `{a}` 等占位符原样保留 |
| `；`（分号） | `do` 数组中的多项动作 | 按顺序依次播放 |
| `＋`（加号） | `together: true` | 与上一个动作同时开始 |
| `‖`（提问分割点） | `- ask: true` | 前面的动作先放，孩子答对后再播放后续动作 |
| `高亮 x` | `- highlight: x` | 可高亮零件或子项（如 `chart.bar.2`） |
| `显示 x` / `隐藏 x` | `- show: x` / `- hide: x` | 单个零件或多零件数组 |
| `x.属性 → 值` | `- set: { target: x, 属性: 值 }` | 可指定 `duration` |
| `x 移到 y` | `- move: { target: x, to: y }` | 移动位置 |
| `从 x 拆 n 个为 y` | `- split: { target: x, take: n, as: y }` | 计数块/十格框拆分 |
| `x 绕 p 转 θ` | `- rotate: { target: x, by: θ, around: p }` | 绕指定点或子项旋转 |
| `x 沿 l 翻折` | `- flip: { target: x, axis: [...] }` | 沿轴翻折 |
| `x 沿 r 走` | `- follow: { target: x, path: ... }` | 沿路径移动 |
| `重复 n 次：…` | `- repeat: "{n}"`<br>`  do: [...]` | 动作级循环展开 |
| `choose 答案 a（选项 …）` | `try:`<br>`  choose: { answer: a, options: [...] }` | 字幕区出选项点选 |
| `drag x → y ×n` | `try:`<br>`  drag: { from: x, to: y, count: n }` | 拖动操作 |
| `tap 答案 …` | `try:`<br>`  tap: { answer: [...], among: [...] }` | 点选零件或子项 |
| `turn x.属性 到 v` | `try:`<br>`  turn: { target: x, prop: ..., answer: ... }` | 转动把手 |
| `sort x 按 k 到 筐` | `try:`<br>`  sort: { from: ..., by: ..., bins: {...} }` | 分类拖放 |
| `place x 到 [x, y]` | `try:`<br>`  place: { target: x, to: [...], rotate: ... }` | 拖动拼接/摆放到位 |
| 任务文字 “...” | `try:`<br>`  task: "..."` | 引号中文字，未写时将讲解转为问句 |
| `提示：…` | `hints: ["..."]` | 错误引导提示数组 |
| `高亮提示：…` | `choose:`<br>`  show: [...]` | 做错后高亮的零件/子项 |

#### 3.5 四条画面核心规则（硬性约束）
1. **颜色强对应**：算式中的数与画面中代表它的元素保持同色（如 `[{a}](@top)`），讲到哪一部分哪一部分高亮。
2. **提问前不给答案**：凡有 `try` 的步骤，画面上不得提前出现答案或得数。必须使用 `- ask: true` 将答题前的画面与答对后的揭晓动作明确分割。
3. **题目说到的画出来，要答的才空着**：提问时题干中已告知的信息全部呈现在舞台上，仅待答内容用闪烁空框（如 `[>](blank)`、`[{ans}](blank)`）占位。
4. **一步只讲一件事**：关键逻辑变化必须配合高亮或动效，避免多件事堆砌在同一步骤。

#### 3.6 核心要点（`keyPoints`）
根据脚本末尾提取 2–4 条总结性要点，语句清晰简练，原意保留。

## 4. 校验与验证流程

编写完成后，依次执行以下命令确保质量：

1. **配置检查**：
   ```bash
   pnpm content:check
   ```
   检查 YAML 语法、schema 校验、零件类型、属性合法性、参数全组合求值与步骤展开上限。出现报错按行号及提示修改。

2. **知识点走查（若工程中已提供 F10 命令）**：
   ```bash
   pnpm check:lessons --lesson <id>
   ```

3. **回归测试与类型构建**：
   ```bash
   pnpm test
   pnpm build
   ```

4. **逐条自校清单（《开发文档》8.1 节）**：
   - [ ] 内容：术语与课标一致，用词契合对应年级，讲解单句 ≤ 30 字，讲清“为什么”。
   - [ ] 画面：颜色强对应，提问前不暴露答案，无多余空置留白，左上角步数不遮挡内容。
   - [ ] 交互：看一看（自动播放）、跟着做（`try` 可做对且做错有提示）、自己做（参数换题后依然成立）。
   - [ ] 多视口表现：在桌面（1280px）、平板（820px）、手机（390px）宽度及深色主题、减少动态效果下检查布局无遮挡和溢出。

## 5. 硬规则（违反将导致合并被拒）

- **不改动核心业务代码**：知识点起草仅新增/修改 YAML 配置文件，不得修改 `packages/`、`apps/`、`server/` 中的 TypeScript 代码。
- **不发明非标属性**：零件与动作只使用《开发手册》及 `scene.md` 明确定义的属性；脚本中未指定的属性沿用 `site.yaml` 默认值。
- **发现脚本问题停下报告**：若脚本存在数学错误、引用的零件或能力尚未实现、逻辑前后矛盾，不得私自更改教学逻辑，须在相关文件末尾“问题记录”中登记并停下向维护人报告。
- **讲解字句保持忠实**：讲解文字严格照抄脚本，不擅自增删或随意修改口吻。
- **状态保留为 draft**：起草的知识点文件初始状态必须为 `status: draft`，待走查与多视口验收通过后再行更新。
