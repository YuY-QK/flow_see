# 动画教学平台 · 评估与设计方案

> 目标：把小学、初中、高中各学科（数理化生等）的知识点做成动画，帮助学生理解原理。
> 状态：待确认。基于当前「动画流」代码（M1–M5 已完成）做评估。

## 1. 结论

1. **不新开项目，也不急着把现有项目拆成独立发布的库。** 在当前仓库里改成**分层的 monorepo**：基础库（core / runtime / blocks）→ 模板包 → 内容包 → 应用。逻辑上就是你说的“基础库 + 上层业务”，物理上先放在同一个仓库里。
2. **当前代码大部分可以直接作为地基**：数据结构、播放状态机、主题、本地存储、分享服务、导出、App 打包都是通用的，不用重写。
3. **要补的是三类东西**：
   - 基础能力：连续时间模型、公式/化学式、可调参数控件、模板插件接口；
   - 积木与学科模板：坐标系、粒子、受力箭头、图解标注等；
   - **内容体系**：知识点分类、元数据、校验、审校流程、素材库。
4. **真正的瓶颈是内容，不是代码。** 基础设施搭好之后，工作量主要在“每个知识点怎么讲、讲得对不对、素材从哪来”，这部分必须有老师参与审校。
5. **先用“垂直切片”验证架构**：每个学科先做 2–3 个知识点，跑通全链路，请老师试用，再批量生产。

## 2. 三个方案怎么选

| | A. 新开项目，重新搭 | B. 当前仓库内分层（推荐） | C. 现在就拆成独立的库仓库 + 业务仓库 |
|---|---|---|---|
| 复用现有成果 | 要么重写，要么复制粘贴 | 全部保留，95 个测试继续有效 | 保留 |
| 接口稳定性 | — | 接口还在变，改起来方便（一次提交改完上下层） | 接口还不稳定，每次改动要跨仓库发版、升级，很拖累 |
| 边界是否清晰 | 看自觉 | 用 workspace 包 + 依赖方向检查强制约束 | 强 |
| 以后能不能拆 | — | 能，包已经分好，拆仓库是机械操作 | — |
| 适用时机 | 现有代码不可用 | **现在** | 接口稳定、多人/多团队、需要对外发布 npm 包时 |

**为什么现在不拆仓库**：基础库的接口（模板怎么写、舞台怎么渲染、时间怎么走）在做完前几个学科的模板之前一定还会调整。分仓库会让每次调整变成“改库 → 发版 → 业务升级 → 联调”，只有一两个人开发时是纯损耗。

**为什么要分层、分包**：内容会有成百上千条，由人和 AI 批量生产。如果没有强制的边界，内容代码会开始依赖界面代码，模板之间互相引用，后面很难收拾。

## 4. 必须补强的基础能力

按优先级排序。前四项是“搭积木”能成立的前提。

### 4.1 连续时间模型（最重要）

**问题**：现在一个动画是“一串步骤快照”，步骤之间靠 Motion 做过渡。这适合流程、排序，但**不适合物理和数学里的连续变化**：抛体运动的轨迹、函数图像随参数连续变化、单摆、波。

**方案**：让舞台变成一个**纯函数**：`画面 = Stage(动画, 第几步, 步内进度 t∈[0,1])`。播放器掌管时钟，驱动 t 前进。

- 好处：能拖动进度条逐帧查看；导出视频时按时间采样，画面可重复、可预测；缩略图也直接取某个时刻。
- 向后兼容：`t` 是可选参数，现有四个模板可以不管它。
- 一个步骤可以声明“连续段”：持续多少秒，舞台在这段时间里按 t 画。

### 4.2 公式与化学式

数学、物理、化学离不开分式、根号、上下标、H₂O、Fe³⁺。

- 建议用 **MathJax 的 SVG 输出**（含 mhchem 化学式扩展）：产出的是自包含的 SVG 路径，可以直接放进舞台，也能被现有的“渲染成静止画面再导出视频/GIF”的流程使用。
- 备选 KaTeX：更快更小，但输出依赖网页字体，导出时处理更麻烦。
- 这一项要先做一个小验证（公式能否在舞台里显示、能否导出、手机上是否清晰），再定。

### 4.3 参数控件与“探究模式”

现在只有“数字列表、下拉选项”两种参数，且只有数据变化模板支持观众改参数。

- 增加**滑块、开关、数值输入**；所有模板都能声明参数；
- 观众可以拖滑块看变化（改 k、b 看直线怎么动；改初速度和角度看抛物线）。这是动画教学相对视频的最大优势，值得做好。

### 4.4 模板插件接口 v2

让“新增一个学科模板”有统一、可检查的写法：

```ts
interface TemplateModule {
  id: string; name: string;
  domain: 'generic' | 'math' | 'physics' | 'chemistry' | 'biology' | '3d';
  elementFields?: FieldDef[];   // 元素表单
  stepFields?: FieldDef[];      // 步骤表单
  paramFields?: FieldDef[];     // 参数（含滑块等）
  generate?(params): Step[];    // 由参数生成步骤
  Stage: Component<{ animation; index; progress; theme; still }>;  // 纯函数
  renderer: 'svg' | 'canvas' | 'webgl';
  exportFrame?(ctx, props): Promise<void>;  // 非 SVG 模板自己提供导出画面
  load: () => Promise<TemplateModule>;       // 按需加载，3D 等大模板不影响首屏
}
```

### 4.5 课程分类与知识点元数据

广场现在只有 6 个粗分类。要改成：**学段 × 学科 × 年级 × 章节 × 知识点**，以课标知识点为主键，教材版本（人教、苏教、北师大等）只做映射。详见第 6 节。

### 4.6 内容校验与开发预览

- `content:check`：校验每条内容符合 schema、引用的模板和素材存在、每一步都有标题和讲解词、元素引用没断。在 CI 里跑。
- 开发预览页：改一个内容文件，浏览器里立刻看到动画（热更新）。

### 4.7 素材库

- 以 **SVG** 为主（可缩放、体积小、能跟随主题变色），放在内容包里，每个素材带来源与许可证信息。
- 不直接使用教材插图（版权问题）；自绘或使用许可证明确的素材。

### 4.8 内容分包与按需加载

内容上千条后不能全部打进首屏。内容按学科/年级分包，首页只加载索引；App 里内容包可以按需下载，避免安装包过大。

## 5. 模板与积木

### 5.1 积木（可复用的小零件）

坐标系与函数曲线、公式、箭头与标注、粒子（原子/分子/离子）、物体（球、方块、斜面、弹簧、滑轮）、电路元件、数轴、图解底图 + 高亮点。模板由积木组合而成，不要每个模板各画各的。

### 5.2 候选模板清单（按学科需求驱动，不是一次全做）

| 领域 | 模板 | 典型知识点 |
|---|---|---|
| 通用（已有） | 流程图、消息传递、循环/时间线、数据变化 | 光合作用、水循环、实验步骤、排序 |
| 数学 | 函数图像（带滑块）、几何作图与变换、数轴与运算过程、统计图表、树状图 | 一次函数、二次函数、全等/相似、平移旋转、概率 |
| 物理 | 运动学（轨迹 + 速度/位移图）、力学（受力、斜面、杠杆、滑轮）、光学（反射/折射光路）、电路（电流流动）、振动与波 | 抛体运动、牛顿定律、光的折射、欧姆定律、单摆 |
| 化学 | 微观粒子反应、实验装置流程、电子排布与周期表、方程式配平 | 分子构成、化学反应的实质、酸碱中和、燃烧 |
| 生物 | 图解标注（底图 + 逐步高亮）、遗传（概率/棋盘）、循环与流程（已有） | 细胞结构、有丝分裂、血液循环、遗传规律 |
| 3D（按需加载） | 立体几何、分子结构、天体运动 | 截面、正四面体、地球公转与四季 |

### 5.3 特殊情况怎么办（保持可扩展）

三层逃生通道，由轻到重：

1. **参数微调**：绝大多数特殊需求靠模板参数解决，不用写代码。
2. **“通用场景”模板**：一个声明式的通用模板，用少量原语（形状、文字、公式、图片、箭头、曲线）加每步的动作描述，覆盖“没有现成模板的一次性动画”。这个模板放到第二阶段再做，先不做完整的动画描述语言。
3. **自定义模板（写代码）**：按 4.4 的接口新增一个模板包，3D、特殊交互走这条路。

## 6. 内容体系

### 6.1 内容数据模型（草案）

```ts
interface ContentItem {
  id: string;                 // 如 'math.junior.g8.function.linear-graph'
  title: string;
  summary: string;            // 一句话简介
  curriculum: {
    stage: 'primary' | 'junior' | 'senior';
    subject: 'math' | 'physics' | 'chemistry' | 'biology' | 'science' | ...;
    grade?: number;
    topicId: string;          // 课标知识点
    textbooks?: { edition: string; chapter: string }[];   // 教材版本映射
  };
  tags: string[];             // 概念 / 过程 / 实验 / 推导 / 易错点
  difficulty: 1 | 2 | 3;
  animation: Animation;       // 复用现有结构：templateId、params、steps、主题
  assets: string[];           // 引用的素材 id
  review: { status: 'draft' | 'reviewed' | 'published'; reviewer?: string; reviewedAt?: string };
  quiz?: unknown;             // 预留：看完后的小测验，第一阶段不做
}
```

内容就是**一份份数据文件**（JSON 或 TS），放在仓库里，用 schema 校验，不需要数据库。以后出现“编辑后台、多人协作审核”再考虑 CMS。

### 6.2 内容生产流水线

```
知识点清单（按课标整理）
   ↓ 优先级筛选：只做“难以理解、过程性/动态性/空间性强”的知识点
选模板 → 写参数与步骤 → 写讲解词（AI 可起草）
   ↓ content:check 自动校验
老师审校（科学准确性、讲法是否适合该年龄）
   ↓ 状态 draft → reviewed → published
发布到广场
```

- **AI 可以大幅提高起草效率**：内容是结构化数据，有 schema，很适合让 AI 按知识点和模板起草，再自动校验。但**审校必须由人完成**，AI 的科学讲解可能出错。
- 审校人、审校时间写进数据里，广场只展示 `published` 的内容。

### 6.3 创作端怎么办

现有的“表单创作”继续保留，老师、学生都可以做自己的动画；官方内容也可以用同一个编辑器起草，再导出成内容文件提交。第一阶段官方内容以“写数据文件 + 开发预览”为主，不急着做专门的内容后台。

## 7. 工程量评估

### 7.1 基础设施（一次性）

| 项目 | 规模 | 说明 |
|---|---|---|
| 重构为分层 monorepo | 中 | 机械迁移 + 边界检查，现有测试保证不出错 |
| 连续时间模型 | 大 | 改播放器时钟、舞台约定、导出采样；要保证旧模板不受影响 |
| 公式/化学式积木 | 中 | 含导出和手机清晰度的验证 |
| 参数控件与探究模式 | 中 | 复用现有“试试改参数”机制 |
| 模板插件接口 v2 + 懒加载 | 中 | |
| 课程分类 + 内容 schema + 校验 + 预览 | 中 | |
| 各学科首批模板（约 6–8 个） | 大 | 函数图像、运动学、微观粒子、图解标注等 |

### 7.2 内容（持续性，量级估算）

我没有逐条统计课标，下面是**规划用的量级估算，不是承诺**：

- 中小学数理化生的知识点总数在千的量级；其中真正适合做动画的（难点、过程性强）大约占一到两成，即几百个。
- 用已有模板、素材齐备时，一个动画（起草 + 自检 + 老师审校）大约需要 1–2 小时；需要新模板、新素材的特殊动画则高得多。
- 按 500 个动画估算，总量大约是 500–1000 人时，其中审校占三成以上。

所以：**基础设施做好，之后的瓶颈是“老师的审校时间”和“素材制作”**，而不是写代码。

## 8. 分阶段路线

| 阶段 | 内容 | 验收标准 |
|---|---|---|
| **0 重构** | 分层 monorepo、边界检查、内容 schema 与元数据、`content:check` | 现有功能与 95 个测试全部保持通过；官方内容迁移成数据文件 |
| **1 基础补强** | 连续时间模型、公式积木、滑块参数、模板接口 v2、课程分类导航 | 一个“带滑块的函数图像”和一个“抛体运动”示例能播放、拖进度、导出视频 |
| **2 垂直切片** | 每个学科（数、理、化、生）+ 小学科学各做 2–3 个知识点，约 10–12 个 | **请老师试用并评审**，用反馈校准模板抽象是否够用 |
| **3 批量生产** | 按需求补模板（总数约 15–25 个）；建立 AI 起草 + 老师审校的流水线；按课标优先级批量出内容 | 每个学段/学科有可用的内容覆盖，审校状态可追踪 |
| **4 扩展** | 3D 模板（Three.js，按需加载）、互动小测、学习记录与账号、内容后台、App 内容包下载 | 按需求取舍 |

阶段 2 是关键的检查点：如果老师评审发现“模板不够用”或“学生看不懂”，要在批量生产前修正，成本最低。

## 9. 主要风险与对策

| 风险 | 对策 |
|---|---|
| 科学内容出错 | 审校流程与状态字段；只发布 `reviewed` 以上的内容；审校人署名 |
| 模板抽象不够通用 | 阶段 2 垂直切片先验证；保留“通用场景”和“自定义模板”两条逃生通道 |
| 内容量太大做不完 | 只做难点；用 AI 起草；同一模板复用；优先级按学段分批 |
| 素材版权 | 自绘 SVG 或使用许可证明确的素材；不使用教材插图；素材带来源与许可证信息 |
| 包体积、性能 | 模板与内容按需加载；3D 单独懒加载；App 内容包按需下载 |
| 课标与教材版本差异 | 以课标知识点为主键，教材版本只做映射 |
| 面向未成年人的合规 | 面向中小学生的网站和 App 上线前，要专门核实国内教育类应用的备案与未成年人个人信息保护要求；账号、统计、评论等功能要特别谨慎。（我没有逐条核实具体规定，上线前需要专业确认） |

## 10. 需要你决策的问题

1. **产品定位**：现有“动画流”是面向任何流程的通用创作工具。教学是它的一个主要场景，还是以后的唯一主线？这决定首页是做成“学习中心”，还是“学习 + 创作”并列。
2. **先做哪些学科/学段**：建议阶段 2 先选一个学段（比如初中）的数、理、化、生各 2–3 个知识点。
3. **有没有老师能参与审校**：这是阶段 2 能否有效的前提。
4. **素材怎么来**：自己绘制、请人绘制，还是使用开源素材？
5. **App 要不要在近期发布**：影响内容分包和备案的优先级。
