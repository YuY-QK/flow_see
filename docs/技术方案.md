# 动画流 · 技术方案与开发计划

> 依据：[产品原型](./产品原型.md)。状态：已确认；M1、M2 已完成。

## 1. 已确认的决定

- **技术栈**：方案 A，网页优先。TypeScript + React + Vite；以后用 Capacitor 打包 iOS / Android App。
- **上线**：先不考虑。第一阶段只在本地运行，服务器和部署以后再定。
- **第一个里程碑**：先跑通核心。在网页上能创建一个动画并播放。

## 2. 技术选型

| 方面 | 选择 | 说明 |
|---|---|---|
| 语言 | TypeScript | 步骤、模板等数据结构都有类型约束 |
| 构建 | Vite | 启动快，配置少 |
| 界面 | React | 生态最大；Capacitor 支持好 |
| 路由 | React Router | 首页、广场、播放、创建、我的、设置 |
| 状态 | Zustand | 轻量；编辑器和播放器状态 |
| 样式 | CSS Modules + CSS 变量 | 视觉规范落成一组设计变量（颜色、圆角、字号） |
| 动画渲染 | SVG + Motion（framer-motion） | 元素位置、透明度等在步骤之间平滑过渡 |
| 本地存储 | IndexedDB（Dexie） | 作品保存在本设备，自动保存 |
| 朗读 | 浏览器 Web Speech API | 免费；以后可换云端语音 |
| 测试 | Vitest | 先覆盖步骤引擎和模板逻辑 |
| 代码规范 | ESLint + Prettier | |
| 包管理 | pnpm | |

## 3. 架构

```
┌──────────────────────── 界面层（React）────────────────────────┐
│  首页 · 广场 · 播放页 · 创建（选模板 / 编辑器）· 我的作品 · 设置 │
│        └── 播放器组件（舞台 + 字幕 + 控制 + 目录 + 改参数）      │
├──────────────────────── 模板层 ───────────────────────────────┤
│  消息传递 · 流程图流转 · 数据变化 · 循环/时间线（每个一个文件夹）  │
│  每个模板 = 表单定义 + （可选）步骤生成器 + 舞台画法              │
├──────────────────────── 引擎层（纯 TypeScript，不依赖 React）──┤
│  作品数据结构 · 时间线/播放状态机 · 主题 · 数据校验与版本迁移     │
├──────────────────────── 服务层 ───────────────────────────────┤
│  本地存储（IndexedDB）· 朗读 · 导出（后续）· 分享（后续，需后端）│
└───────────────────────────────────────────────────────────────┘
```

**关键原则**
1. **引擎层不依赖界面**：以后 App、导出视频都复用同一套引擎。
2. **模板即插件**：新增模板 = 新增一个文件夹并注册，不改其他代码。
3. **步骤是唯一数据源**：播放、目录、字幕、朗读、导出都从同一份步骤数据来。
4. **账号预留**：作品数据里预留 `author`、`ownerId` 字段；存储走统一接口，以后可以把“本地存储”换成“本地 + 云端同步”。

## 4. 核心数据结构（草案）

```ts
// 一个动画作品
interface Animation {
  id: string;
  schemaVersion: number;      // 数据格式版本，便于以后升级
  title: string;
  author?: string;            // 署名（与账号无关）
  ownerId?: string;           // 预留：以后接账号
  templateId: string;         // 'message' | 'flow' | 'data' | 'cycle' | ...
  themeId: string;            // 'pro' | 'flat' | 'cute' | 'chalk'
  elements: Element[];        // 参与者/节点等，结构由模板定义
  steps: Step[];              // 手填的步骤（表单模式）
  params?: Record<string, unknown>; // 生成器参数（如要排序的数字）
  settings: { autoNarrate: boolean; allowParamEdit: boolean };
  createdAt: number;
  updatedAt: number;
}

interface Step {
  id: string;
  title: string;              // 这一步发生了什么
  desc: string;               // 一句话解释（显示 + 朗读）
  narration?: string;         // 单独的朗读文本
  duration?: number;          // 停留时长，空 = 按朗读长度自动
  data: Record<string, unknown>; // 模板专属字段（如 from / to / label）
}

// 一个模板
interface Template {
  id: string;
  name: string;
  elementFields: FieldDef[];        // “参与者”表单
  stepFields: FieldDef[];           // 步骤表单；FieldDef.advanced=true 的进“更多设置”
  createDefault(): Animation;       // 新建时的示例内容
  generate?(params): Step[];        // 可选：参数生成步骤（数据变化类）
  Stage: React.FC<StageProps>;      // 画出“第 N 步时的画面”
}
```

## 6. 开发计划

### M1：跑通核心（已完成）

**目标**：在网页上能新建一个“消息传递”动画，编辑步骤，实时预览，播放（带字幕和朗读），刷新后作品还在。

| # | 任务 |
|---|---|
| 1 | 项目脚手架：Vite + React + TS、ESLint/Prettier、Vitest、设计变量 |
| 2 | 引擎：数据结构、播放状态机（播放/暂停/上一步/下一步/跳转/调速）及单元测试 |
| 3 | 4 个动画主题（设计变量形式） |
| 4 | 模板：消息传递（表单定义 + 舞台画法） |
| 5 | 播放器：舞台、字幕、控制条、进度条、步骤目录、朗读 |
| 6 | 编辑器：选模板页 → 编辑器（参与者、步骤卡片、更多设置、添加/删除/拖动排序、外观面板、实时预览） |
| 7 | 本地存储：自动保存；简易“我的作品”列表作为入口 |

**验收**：照着原型完成“TCP 三次握手”从新建到播放的全过程；电脑和手机浏览器都能用；引擎测试通过。

### 后续里程碑

- **M2 模板补全（已完成）**：流程图流转、数据变化（含“改参数重播”，以冒泡排序为例）、循环/时间线
- **M3 页面补全**：首页、动画广场（官方内容以内置数据提供）、我的作品完整版、设置、播放页完整版
- **M4 分享与导出**：选定后端，实现短链接分享与分享打开页；导出视频 / GIF
- **M5 App**：Capacitor 打包 iOS / Android，手机端细节打磨
