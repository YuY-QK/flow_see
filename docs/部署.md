# 部署

网页和分享接口有两种部署方式，共用同一份接口逻辑（`server/share-api.mjs`，标准 Request/Response 写法）：

| 方式 | 网页 | 分享接口 | 分享数据 |
|---|---|---|---|
| **Cloudflare Pages**（当前采用） | Pages 静态托管，单页应用自动回退到 `index.html` | Pages Functions：`functions/api/[[path]].js` | Workers KV（绑定名 `SHARES`） |
| 自己的服务器 | `pnpm start`（Node 服务同时提供网页） | 同一个 Node 服务：`server/app.mjs` | `DATA_DIR` 下的 JSON 文件 |

换部署方式时只换存储实现；前端的接口地址在 `packages/content/site.yaml` 的 `share.apiBase`。

## Cloudflare Pages

### 推荐：GitHub Actions 自动部署（`.github/workflows/deploy.yml`）

只需做一次：

1. Cloudflare 控制台 → 右上角头像 → My Profile → API Tokens → Create Token → Create Custom Token，权限选：
   - Account · **Cloudflare Pages** · Edit
   - Account · **Workers KV Storage** · Edit

   Account Resources 选你的账号。
2. GitHub 仓库 → Settings → Secrets and variables → Actions → New repository secret，添加：
   - `CLOUDFLARE_API_TOKEN`：上一步的 token
   - `CLOUDFLARE_ACCOUNT_ID`：Cloudflare 控制台首页右侧栏的 Account ID

之后：

- 推送到 `main` → 自动检查（lint、测试、内容检查、类型检查）→ 部署到生产地址 `https://flow-see.pages.dev`。
- 其他分支：GitHub → Actions → “部署到 Cloudflare” → Run workflow，选分支 → 得到预览地址。
- 第一次运行时 `scripts/cf-setup.mjs` 会自动创建 KV 命名空间 `flow-see-SHARES` 和 Pages 项目 `flow-see`，以后重复运行不会重复创建。

### 另一种方式：Cloudflare 控制台连接 GitHub

不想用 Actions 时，也可以在控制台手动配置：

1. 创建 KV 命名空间，把输出的 `id` 填进根目录 `wrangler.toml` 的 `[[kv_namespaces]]`：

   ```bash
   pnpm exec wrangler login
   pnpm exec wrangler kv namespace create SHARES
   ```

2. 在 Cloudflare 控制台 → Workers & Pages → 创建 Pages 项目 → 连接 GitHub 仓库 `yuy-qk/flow_see`，构建设置：

   | 项目 | 值 |
   |---|---|
   | 框架预设 | 无 |
   | 构建命令 | `pnpm build` |
   | 构建输出目录 | `apps/web/dist` |
   | 根目录 | （留空，仓库根目录） |
   | 环境变量 | 不需要（Node 版本由 `.node-version` 指定为 22，pnpm 版本由 `package.json` 的 `packageManager` 指定） |

   项目名与 `wrangler.toml` 的 `name` 保持一致（`flow-see`），这样 KV 绑定会按 `wrangler.toml` 生效；也可以在控制台“设置 → 绑定”里手动添加 KV 绑定 `SHARES`。

3. 之后每次推送到生产分支，Cloudflare 自动构建上线；其他分支生成预览地址。

`pnpm build` 会依次运行 `pnpm content:check`（内容配置有错时中止构建）、类型检查和打包。

### 本地模拟 Cloudflare

```bash
pnpm build
pnpm cf:dev        # wrangler pages dev：本地 workerd + 本地 KV，http://localhost:8788
```

也可以不经过 GitHub 直接上传：`pnpm cf:deploy`（需要先 `wrangler login`）。

### 相关文件

- `wrangler.toml`：Pages 项目名、输出目录、KV 绑定
- `functions/api/[[path]].js`：`/api/*` 的入口；其余路径是静态网页，不会触发 Functions
- `apps/web/public/_headers`：打包产物长期缓存，`index.html` 每次检查更新
- `server/kv-store.mjs`：KV 存储实现（键 `share:<id>`）

## 自己的服务器（Node）

```bash
pnpm install
pnpm build
PORT=8787 DATA_DIR=/var/lib/flow-see/shares pnpm start
```

分享数据是一份份 JSON 文件，备份 `DATA_DIR` 即可。从 Cloudflare 迁移过来时，把 KV 里 `share:<id>` 的值导出成 `<id>.json` 放进 `DATA_DIR`。
